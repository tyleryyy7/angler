# qmt/ — 大QMT 内置执行器

## 文件
- `executor_v2.py` — **当前版**：对齐扫描器 ESI v2 规则。进场 = 1h 上穿 + R1 小周期闸门
  （30m/15m/5m 任一处于下行段 fish<trigger 则不买，进待激活观察）；R2 假性失效观察：
  被拦的票每根 bar 复查，三周期全部回到上行且 1h 趋势未破（fish>trigger）→ 激活买入，
  1h 破趋势 → 作废；离场 = 1h 下穿全卖（正常离场）+
  R3 亏损即卖（完结 30m 下穿且现价 < 成本 → 立即全卖，浮盈继续持有）。
  需在客户端下载 1h/30m/15m/5m 历史；建议策略运行在 5m 周期（检查频率高）。
  注意：待激活状态在内存中，策略重启即清空（重启后如仍有需要会在下次上穿时重新评估）。
- `executor_v1.py` — 旧版（仅 1h 上穿买/下穿卖，无小周期闸门和 ESI 离场），留档。
- `watchlist.txt` — 手动标的清单（每行一个标准代码，`#` 注释）。
  **运行副本必须放在纯英文路径 `D:\qmt\watchlist.txt`**（大QMT 内置环境按 GBK 读源文件，
  路径含中文会直接 SyntaxError；仓库里这份是模板，改清单改 D:\qmt 那份）。

## 部署步骤
1. 把 `executor_v1.py` 内容拷入大QMT 策略编辑器（源文件 UTF-8；内置环境 py3.6、
   无 pandas，勿引入外部库）。
2. 修改文件头部配置：`ACCOUNT_ID`（资金账号）、`VOLUME`（每单股数）、
   `WATCHLIST_FILE`（清单路径，**必须纯英文路径**，中文路径会 SyntaxError）、
   `USE_ENTRY_GATE`（买入闸门 0<fish<2.5 开关）。
   `PERIOD` 默认 `'1h'`——国金这个构建的 get_history_data **不认 '60m'**（报
   "不支持'60m'数据周期"），用 '1h'；回测/运行界面的周期也选「1小时」。
3. 客户端「数据管理 → 补充数据」下载清单内标的的 60 分钟 K 线（至少 3 个月），
   否则历史不足只打印 warming up。
4. 先回测模式短区间验证（信号不重复、成交一一对应），再模拟盘，再实盘。

## 信号语义（与 fisher_scanner.py 一致）
- 上穿（买）：fish[-1] > fish[-2] 且 fish[-2] <= fish[-3]，即费雪由跌转升拐点
- 下穿（卖）：fish[-1] < fish[-2] 且 fish[-2] >= fish[-3]，即由升转跌拐点
- 买入闸门（ESI 进场条件）：0 < fish < 2.5
- 持仓以账户实际持仓为准（get_trade_detail_data），策略重启不丢状态；
  同一根 bar 不重复下单。

## 注意
- 穿仓/废单等以券商端返回为准；市价单（priceType=5）注意流动性差的票。
- R3 浮亏判定需要持仓成本价：执行器按 m_dOpenPrice/m_dPositionCost/m_dCostPrice
  顺序尝试读取；若你的账户对象字段名不同（打印持仓对象 dir 确认），改 `get_position`。
- 仓位固定股数（VOLUME），无资金管理。
- 9/11 新规环境，实盘前先问客户经理内置策略报备流程。
